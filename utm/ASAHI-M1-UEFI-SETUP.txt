Eve — AArch64 UEFI on M1 Pro (and other Apple Silicon) via Asahi Linux
=======================================================================

**Self-contained Linux install bundle (tar/rsync one folder):**

  install/linux-asahi-m1/   — see INSTALL.txt; scripts populate EFI + GRUB on Asahi.

This uses the same **`BOOTAA64.EFI`** as QEMU/UTM (`kernel-arm-uefi`), *not* the x86
Eve shell (`utm/eve-bios.img`). You get the small UEFI demo: serial text + solid
GOP fill, then exit after a few seconds.

Asahi’s boot chain is documented here:
https://asahilinux.org/docs/alt/boot-process-guide/

Important facts:

  Apple firmware → m1n1 → U-Boot → **\EFI\BOOT\BOOTAA64.EFI** (normally GRUB) → Linux

  • There is **no persistent UEFI boot order** on Apple Silicon Asahi; U-Boot always
    loads the **default** path above.
  • **Do not delete GRUB** without a recovery plan. Prefer **chainload** or **USB**.

Kernel needed to boot **Asahi** (vs what Eve provides)
--------------------------------------------------------
  • **Asahi Linux** is booted by your **distro’s Linux kernel** (Fedora Asahi, Arch,
    Ubuntu Asahi, etc.) — the one the Asahi installer puts under `/boot` and that
    GRUB’s default entry loads (`vmlinuz` + initramfs). You do **not** get that
    kernel from the Eve repo; install and update the OS with your distribution’s
    packages. Official overview: https://asahilinux.org/

  • **Eve** does **not** ship a replacement kernel for Asahi. The Eve crate named
    `kernel-arm-uefi` builds **`BOOTAA64.EFI`**, which is a **UEFI application**
    (like a small program U-Boot/GRUB can chainload), **not** a Linux kernel. It
    does not boot your whole system; it runs the short demo, then returns.

  • **Daily Asahi boot:** use GRUB’s normal Linux entry — same kernel as before Eve.
    **Try Eve:** pick **“Eve OS (AArch64 UEFI demo)”** in GRUB; that chainloads Eve’s
    EFI binary instead of `vmlinuz` for that one boot.

Apple boot picker **with** GRUB (normal dual-boot flow)
-------------------------------------------------------
You **do** use the Apple picker and **do** use GRUB — they are two different menus:

  1. **Shut down**, then **hold the power button** until “Loading startup options”
     (or the boot-picker UI appears).
  2. Choose the **Asahi / Linux** volume (Fedora Asahi, Arch, etc.) — **not** macOS
     if you want Linux. Apple’s list shows **OS volumes**, not individual GRUB lines.
     There is **no separate Apple icon for Eve**; Eve is **not** a macOS-style app
     tile here.
  3. That choice boots **Apple firmware → m1n1 → U-Boot → GRUB** (same as a normal
     Linux boot on this machine).
  4. When the **GRUB** menu appears, select **“Eve OS (AArch64 UEFI demo)”** (after
     you ran `asahi-grub-add-eve.sh` or `install-on-asahi.sh`).

Summary: **Apple picker = which installed OS / volume to start.** **GRUB = what to
run inside that Linux install** (default kernel, Eve chainload, etc.). Eve always
shows up in **GRUB**, not as its own row in the Apple startup list (unless you use
a separate USB / recovery path documented elsewhere).

1) Build on the Mac (Asahi Linux, native AArch64)
   From the Eve repo:

     rustup toolchain install nightly
     rustup component add rust-src --toolchain nightly
     rustup target add aarch64-unknown-uefi
     sudo apt install mtools          # Debian/Ubuntu/Fedora: dnf install mtools

     ./scripts/arm-uefi-sync.sh

   Artifacts:

     utm/arm-uefi/bootaa64.efi
     utm/arm-uefi/eve-arm-uefi-fat.img   (ESP with EFI/BOOT/BOOTAA64.EFI)

   Or: `./scripts/build-all-images.sh` (includes this step when mtools is present).

2) Recommended: automated GRUB menu (m1n1 + U-Boot unchanged; default boot intact)
   This does **not** replace `/EFI/BOOT/BOOTAA64.EFI` (GRUB). It adds
   `/EFI/EVE/BOOTAA64.EFI` and an `/etc/grub.d/41_eve_os` snippet, then runs
   `grub-mkconfig` / `update-grub`.

   From the Eve repo on **Asahi Linux (aarch64)**:

     ./scripts/arm-uefi-sync.sh
     sudo ./scripts/asahi-grub-add-eve.sh

   Optional: `sudo ./scripts/asahi-grub-add-eve.sh /path/to/bootaa64.efi`

   Remove the menu entry and EFI copy:

     sudo ./scripts/asahi-grub-add-eve.sh --remove

   Override ESP mount if needed: `sudo ESP=/your/esp ./scripts/asahi-grub-add-eve.sh`

   Reboot → GRUB → **“Eve OS (AArch64 UEFI demo)”** → Eve EFI → green screen briefly.

   **GRUB icon:** the menu entry uses `--class efi --class gnu-linux` so graphical
   themes can show the same style of icon as “UEFI Firmware Settings” / Linux
   entries. If you still see no icon, your theme may ship few icons — the entry
   text still works. After updating Eve’s snippet, run `sudo update-grub` (or
   re-run `asahi-grub-add-eve.sh` / `install-on-asahi.sh`).

   **Apple startup options:** see the section **“Apple boot picker with GRUB”** above
   — pick Linux in Apple’s UI, then Eve in GRUB. USB sticks may show a generic
   external icon or not appear, depending on firmware and partitioning; internal-disk
   installs should use that two-step flow.

3) Manual GRUB snippet (if you prefer not to use the script)
   Same as before: copy to `/boot/efi/EFI/EVE/BOOTAA64.EFI`, add a `menuentry` with
   `insmod part_gpt`, `insmod fat`, **`insmod chain`** (arm64-efi ships `chain.mod` only;
   do **not** use `insmod chainloader` — that module does not exist and can produce
   misleading “chainloader” / loader errors), then `search --fs-uuid …` and
   `chainloader /EFI/EVE/BOOTAA64.EFI`, then regenerate GRUB.
   Use `--class efi --class gnu-linux` on the `menuentry` line if you want theme
   icons (see §2).

4) USB stick (does not touch internal ESP)
   Write the FAT image to a USB drive from Linux (replace `sdX` carefully):

     sudo dd if=utm/arm-uefi/eve-arm-uefi-fat.img of=/dev/sdX bs=4M conv=fsync status=progress

   Boot holding the power button (Apple boot picker) and choose the USB volume if
   offered, or use Asahi/m1n1 USB UEFI “container” behaviour as described in the
   Asahi boot guide for installer/rescue images.

5) Last resort: temporary swap of default BOOTAA64.EFI
   **High risk:** replacing `/boot/efi/EFI/BOOT/BOOTAA64.EFI` removes GRUB from the
   default path until you restore it.

     sudo cp /boot/efi/EFI/BOOT/BOOTAA64.EFI /boot/efi/EFI/BOOT/BOOTAA64.GRUB.bak
     sudo cp utm/arm-uefi/bootaa64.efi /boot/efi/EFI/BOOT/BOOTAA64.EFI

   Restore after testing:

     sudo cp /boot/efi/EFI/BOOT/BOOTAA64.GRUB.bak /boot/efi/EFI/BOOT/BOOTAA64.EFI

6) What works vs does not
   • Works: running Eve’s **AArch64 UEFI application** under U-Boot’s UEFI services
     on real M1 Pro-class hardware (same binary as QEMU `virt` in most cases).
   • Does not: the full **x86** Eve OS in UEFI (wrong architecture). Use QEMU/UTM
     or a PC for `utm/eve-bios.img` / `utm/eve-uefi.img`.
   • GOP vs serial: if the display stays black, connect/use serial if your U-Boot
     build prefers UART (Asahi docs mention stdout-path behaviour).
